HTTP 请求与响应：用 curl 看见你的检测 API

这一课不写服务端代码；目标是能画出一次调用的完整往返，并亲手用 curl 发出请求、读出报文的每一段。

预计 25 分钟 阶段：HTTP 基础 · 第 1 周 输出：一次亲手发起的请求与标注过的报文

通用图像分类示例

本课使用合成图像分类例子：客户端提交图像，服务端返回一个假分类结果。先理解报文结构，再用自己的最小示例实现端点；例子不对应任何实际业务系统。

一次调用由什么构成

HTTP 是请求—响应协议。这里展示的是 HTTP/1.1 的文本格式：请求行（方法 + 路径 + 版本）、头部（键值对元数据）、空行之后可选的请求体；响应对应状态行、头部和响应体。请求体和响应体可以是二进制数据，不能把整个 HTTP 协议称为纯文本；HTTP/2 和 HTTP/3 使用不同的二进制分帧。参见 RFC 9112 §2.1 与 MDN HTTP 消息。

请求                           响应
POST /detect HTTP/1.1          HTTP/1.1 200 OK
Host: 192.0.2.20:8000        Content-Type: application/json
Content-Type: image/jpeg       Content-Length: 187

<图像二进制字节>                 {"predictions": [
                                   {"class": "sample",
                                    "score": 0.93,
                                    "box": [x1, y1, x2, y2]}
                                 ]}

报文每一段的名字与图解，看 MDN：HTTP 消息——本课的权威参考。

方法与状态码在检测场景的对应

  • GET /health：问「服务器活着吗」，没有请求体；GET /models：取模型信息。
  • POST /detect：提交一张图像（请求体）换回检测结果。图像是提交给服务器处理的输入，所以用 POST——GET 的语义是「取资源」；GET 请求内容没有通用定义的语义，客户端通常不应发送，部分实现会拒绝它，并非报文格式绝对禁止请求体。参见 RFC 9110 §9.3.1。
  • 状态码三大家族：2xx 成功；4xx 表示「客户端的请求有问题」（404 路径不存在、413 图像太大、415/422 格式不被接受）；5xx 表示「服务器自己出了问题」。排障先看首位数字：先判断该改请求，还是该查服务端。

检索练习

把一张合成图像发给服务器做检测，应该用哪个请求？

25 分钟行动

  1. 终端运行 curl --http1.1 -v https://httpbin.org/get（无外网时换成局域网内任一服务），对照上面的结构，在输出里圈出五段：请求行、请求头、状态行、响应头、响应体。
  2. 把 -v 换成 -s -o /dev/null -w "%{http_code}\n"，只取状态码——体会「状态码只是整个报文的一行」。
  3. 若 demo 已能启动：对它的地址（如 http://<server-ip>:<port>/docs 或健康检查端点）各来一次 curl，记下状态码。
