QKV 与 KV cache 速查

用一个 Decoder-only Transformer 层的视角，区分训练时的并行 attention 与生成时逐 token 的 cache。

Q、K、V 从同一层输入投影而来

对每个 token 的隐藏向量 H，使用三组可学习线性投影得到 Q、K、V。一个有用的记忆法是：Q 表示当前位置想匹配什么，K 表示每个位置可被匹配的索引，V 表示匹配后取回的内容。

Q = H WQ
K = H WK
V = H WV

attention(Q, K, V) = softmax(Q Kᵀ / √d_head + causal_mask) V

这个记忆法用于理解，不代表 Q、K、V 来自三份不同文本；在自注意力中三者都由同一序列的 H 投影得到。

常用张量形状

张量形状含义
H[batch, seq, d_model]一层 attention 的输入隐藏状态。
Q/K/V[batch, heads, seq, d_head]分头后的三类投影；d_model = heads × d_head。
scores[batch, heads, query_seq, key_seq]每个 query 对每个 key 的注意力分数。
KV cache每层各一对 K/V，序列维持续增长生成时复用已处理前缀的信息。

因果注意力

在位置 t，mask 屏蔽 t 之后的 key，因此当前位置只能读取过去和当前 token。这个限制既保证训练目标合法，也使过去 token 的 K/V 在未来生成时保持可复用。

KV cache：只为逐 token 推理省重复计算

阶段一次 forward 输入是否使用 KV cache
训练整段 batch，可并行处理所有位置否；先把全序列训练链路做对。
Prefill生成前的完整 prompt建立每层已有 token 的 K/V。
Decode最新的一个或少量 token是；将新 K/V 追加到缓存，并用当前 Q 读取全部过去 K/V。
 
cache_K = concat(past_K, current_K)
cache_V = concat(past_V, current_V)
output = attention(current_Q, cache_K, cache_V)

缓存的是过去的 K/V，而不是过去的 Q：生成下一个 token 时只需要当前 token 的 query 去查询已有上下文。cache 按层保存，序列越长占用的显存越多。

项目决策

第一个 mini LLM 基线先实现无 cache 的训练与生成，作为正确性对照。只有在生成正确且有简单 benchmark 后，再实现 KV cache；届时应验证“有 cache 与无 cache 的 logits/生成在相同设置下匹配”。
